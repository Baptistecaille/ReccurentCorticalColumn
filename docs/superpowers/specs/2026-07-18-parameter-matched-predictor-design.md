# Parameter-Matched Predictor Arm — Design

**Date:** 2026-07-18
**Status:** Approved

## Problem

The two-epoch ResNet-18 comparison currently pits a 9,451,520-parameter MLP
projector against a 6,508,288-parameter `FixedTreePredictor` head. The predictor
scored 2.76% worse on VICReg total while carrying 31.1% fewer head parameters,
so the quality gap cannot be attributed to architecture: it may simply reflect
the smaller capacity budget.

`validate_config` pins `model.feature_dim=512`, `model.mlp_hidden_dim=2048`, and
`model.output_dim=2048`, so the baseline projector is fixed at 9,451,520
parameters and cannot be shrunk without breaking fidelity to the official
EB-JEPA projector. The cortical head must therefore grow to meet it.

## Goal

Add a third arm whose head parameter count matches the baseline within 1%, while
keeping the existing predictor arm so that capacity effects and architecture
effects can be separated.

## Parameter Matching

Free cortical knobs are `n`, `L_max`, `dim_hidden`, `dim_feedback`, and `dim_U`
(`dim_in` and `dim_target` are pinned to `feature_dim` and `output_dim`). Most
are coarse — `dim_hidden=384` alone overshoots to 12,348,416. `dim_U` provides
the primary step and `dim_feedback` a fine adjustment of roughly 4,600
parameters per unit.

Selected configuration:

| Arm | dim_hidden | dim_U | dim_feedback | Head params | vs baseline |
|---|---|---|---|---|---|
| `baseline` (MLP projector) | — | — | — | 9,451,520 | — |
| `predictor` | 256 | 256 | 128 | 6,508,288 | −31.1% |
| `predictor_matched` | 256 | 512 | 168 | 9,447,920 | **−0.038%** |

The matched arm differs from `predictor` on exactly two values: `dim_U`
(256 → 512) and `dim_feedback` (128 → 168). `n`, `L_max`, and `dim_hidden` are
unchanged, so the tree topology is identical and only its width grows.

## Architecture

### New config file

`configs/cortical_matched.yaml` is a copy of `configs/cortical.yaml` with
`cortical.dim_U: 512` and `cortical.dim_feedback: 168`, plus a header comment
recording that it is the parameter-matched variant and what differs. It is a new
file; `baseline.yaml` and `cortical.yaml` are not modified.

Placing the dimensions in YAML rather than in per-arm overrides keeps
`SHARED_OVERRIDES` strictly identical for all three arms, so protocol equity
stays visible at a glance and no per-arm override machinery is needed.

### Notebook changes

The notebook is generated by `scripts/build_resnet18_two_epoch_comparison.py`;
all edits go to the builder, which is then re-run to regenerate the `.ipynb`.

- `ARM_LABELS` becomes `("baseline", "predictor", "predictor_matched")`.
- `CONFIG_PATHS` gains a third entry pointing at `cortical_matched.yaml`.
- `EXPECTED_HEADS` gains `predictor_matched → cortical`.
- The shared-value agreement loop compares each arm **against the baseline**
  instead of a single hard-coded pair. It covers data, loss, and optimization
  paths only, so the intentional `cortical.*` differences are not flagged.
- `COMPARISON_METRICS` becomes row-oriented: `comparison_table` carries
  `(arm, metric, baseline, arm_value, absolute_change, percentage_change)` for
  each predictor arm against the baseline. `derive-takeaways` and the compute
  ratio plot consume the new `arm` column.

`train-models`, `evaluate-checkpoints`, and `profile-models` already iterate
`for label in ARM_LABELS` and generalize without modification.

### Parameter parity guard

A new `parameter-parity` cell runs **after `protocol-checks` and before
`train-models`**. It builds all three heads — instantaneous, no training — and
asserts the match before any GPU time is spent:

```python
PARITY_TOLERANCE = 0.01  # 1%
head_params = {
    label: count_parameters(build_model(configs[label])).head
    for label in ARM_LABELS
}
relative_gap = (
    abs(head_params["predictor_matched"] - head_params["baseline"])
    / head_params["baseline"]
)
assert relative_gap <= PARITY_TOLERANCE, (head_params, relative_gap)
```

It then displays a parity table of head, backbone, and total parameters per arm.
If a future edit breaks the match, this fails in seconds with the counts shown,
rather than after three training runs.

## Testing

`tests/test_resnet18_two_epoch_notebook.py` is extended with structural
assertions: the `parameter-parity` cell exists and references
`PARITY_TOLERANCE`; the third arm label and its config path are present; and the
new YAML declares `dim_U: 512` and `dim_feedback: 168`. A non-notebook test
asserts that the matched head is within 1% of the baseline head by constructing
both from `cortical_matched.yaml` and `baseline.yaml` — a fast
model-construction check that runs without training.

That parity test must load both configs with the same protocol overrides the
notebook uses (at minimum `optimization.learning_rate=0.3` and
`optimization.warmup_start_lr=0.00003`). `configs/baseline.yaml` presently
carries uncommitted working-tree edits (`learning_rate: 1`,
`warmup_start_lr: 0.3`) that fail `validate_config`; loading it bare would make
the new test fail for reasons unrelated to parameter parity, exactly as it
currently fells `tests/test_model_backbone_config.py`. Applying the overrides
keeps the test measuring parameter counts rather than config drift. Head
parameter counts are unaffected by these optimization values.

Every assertion is verifiable without executing the experiment, preserving the
constraint that repository validation never runs the two-epoch training.

## Cost

One additional training run of roughly 190s, bringing the notebook to about
10 minutes end-to-end on a Colab GPU, plus one more profiling pass.

## Expected Outcome

Comparing `predictor` (6.51M) and `predictor_matched` (9.45M) against the same
baseline decomposes the observed 2.76% quality gap into a capacity component and
an architecture component. It also tests whether the elevated VICReg variance
term seen in the predictor arm — indicating drift toward representational
collapse — worsens or resolves with additional capacity.

## Out of Scope

Multi-seed training. The single training seed still prevents attributing any
remaining gap to architecture with statistical confidence; that would require
seeds 1/1000/10000 per arm and triples the cost. Noted as a known limitation.
